## Building

```bash
./gradlew :app:assembleDebug        # debug APK
./gradlew :app:installDebug         # install on a connected device
./gradlew :domain:build             # build just the game-rules module
```

Or open the folder in Android Studio and run the `app` configuration.

> There are currently no unit tests in the repository. `domain` is pure Kotlin, so it is the easiest place to add them: for example, run `CombatEngine` with a fixed `DeterministicRng` seed and assert on the outcome.

## Configuration (`local.properties`)

`local.properties` is git-ignored, so keep secrets here. All keys are optional.

```properties
# Google OAuth *web* client id, used by "Sign in with Google" and Drive backup.
GOOGLE_WEB_CLIENT_ID=1234567890-abc123.apps.googleusercontent.com

# Comma, semicolon or space separated list of accounts that get the in-app admin tools.
ADMIN_EMAILS=you@example.com, tester@example.com
```

- The client id may also be supplied as `oauthid`, `OAUTH_ID` or `oauth_id`, or as a Gradle property (`-PGOOGLE_WEB_CLIENT_ID=...`).
- `ADMIN_EMAILS` may also be a Gradle property (`-PADMIN_EMAILS=...`).
- Both become `BuildConfig` fields.

### Google sign-in and Drive

1. In Google Cloud Console, create an OAuth client of type **Web application**. Put its id in `GOOGLE_WEB_CLIENT_ID`.
2. Create an **Android** OAuth client for your package (`com.sushanth.onlysticks`) and signing-key SHA-1. Credential Manager needs it to work.
3. Enable the **Google Drive API**. The app only requests the `drive.appdata` scope (a hidden per-app folder).

Without a client id, the sign-in button is disabled (`GoogAcctClient.isConfigured == false`).

### Offline / debug mode

Debug builds show a **Continue offline** option, which skips Google sign-in. To get admin tools while offline, add the pseudo-account `offline@debug.local` to `ADMIN_EMAILS`.

### Google Play Games (optional)

Fill in `app/src/main/res/values/games-ids.xml` with your Play Games project id and event ids. If `game_services_project_id` is empty, Play Games is never initialised. Stats are counted locally either way and sent when available.

### Health Connect

Step rewards need the Health Connect app and the "Steps" read permission. The app asks on first launch. Without them, step sync quietly does nothing.

## Common tasks

| Task | Where |
|---|---|
| Rebalance the game (HP, damage, prices, drop rates, bot difficulty) | `domain/.../config/Cfg.kt` |
| Change move stats | `domain/.../model/Move.kt` |
| Change who beats whom | `domain/.../combat/InteractionMatrix.kt` |
| Change rarity stat ranges or colours | `domain/.../model/Rarity.kt` |
| Add a database column/table | Entity + DAO, bump `AppDatabase.version`, add a migration in `Migrations.kt`, commit the new `app/schemas/*.json` |
| Add UI text | `app/src/main/res/values/strings.xml` |
| Add a sound | Put a `.wav` in `res/raw`, add an entry to `SoundFx` in `audio/SoundMgr.kt` |
| Add an icon | Write a `buildX()` function in `ui/components/*Icons.kt` and expose it in `GameIcos` |
| Change colours/fonts | `ui/theme/Color.kt`, `Type.kt` |

## Historical names

The project was once called **StickDeck**. You'll still see that name in the database file (`stickdeck.db`), Keystore aliases (`stickdeck.*`) and the commit-hash tag. Renaming any of these would break existing installs: the database could no longer be found or decrypted, and card signatures would fail.
